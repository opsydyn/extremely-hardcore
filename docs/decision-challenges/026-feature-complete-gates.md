# decision challenge: feature-complete gates

## trigger

This proposal changes the lifecycle state machine, public local CLI contracts, CI behaviour, evaluation thresholds, and evidence presentation.

## proposal

Implement the five remaining V0 gates as local, schema-version-1 extensions while retaining the current protocol as the sole semantic authority.

## platform ownership and repository value

GitHub Actions already owns job scheduling and pull-request presentation. Bun already owns local command execution. The repository value is the portable run contract, risk-adjusted validation, durable approval linkage, scenario policy, and honest derived summaries that can be consumed by those systems.

## strongest counterargument

This is too much workflow for a skills repository. A lifecycle expansion could create a small bespoke tracker that users bypass, while declared evaluations and local attestations could create the appearance of rigour without proving agent behaviour.

## claim-to-evidence map

| Claim | Current evidence | Gap | Required evidence |
| --- | --- | --- | --- |
| The lifecycle can reject illegal and stale actions. | Existing guarded completion and fingerprint checks. | No blocked, abandoned, decision, or approval records. | Focused transition and stale-approval tests. |
| The full corpus can be assessed repeatedly. | 20-scenario manifest and separate deterministic/attempt assessors. | No shared repetition policy or fail-closed aggregate. | Policy tests and repeated local report. |
| CI can show protocol state without trusting prose. | CLI validation and JSON protocol. | No stable delivery artefacts. | Summary/attestation tests and reference workflow. |
| Ten dogfood runs demonstrate operating readiness. | Five historical completion-gate records. | No controlled aggregate or friction schema. | Ten-run report plus explicit real-world limitation. |
| Provider expansion should wait. | Held live Codex isolation/provenance and deferred Claude/Pi roadmap. | No V0 completion evidence yet. | Keep adapters excluded until all gates are evidenced. |

## minimum credible slice

One backward-compatible protocol extension with legal lifecycle transitions, high-risk approval freshness, status output, a policy-backed full-corpus assessor, CI artefacts, and a controlled dogfood report. No provider execution or hosted integration.

## falsifiable stop conditions

- Any existing V1 fixture or command breaks without an explicit migration.
- Transition validation permits a terminal-state escape or stale high-risk approval.
- CI artefacts contain claims not derivable from validated records.
- The evaluator accepts missing scenario coverage or hides critical failures.
- Controlled dogfood cannot prove its own count and failure status.

## verdict

proceed
