# ADR: proportionate guidance and functional domain modelling

## status

accepted, 2026-11-12; the user approved the combined scope before implementation.
Supersedes ADR 0023's mandatory five-field presentation, and amends ADR 045's
fixed simplicity-check presentation. Their standalone-method boundaries remain.

## context

The Flow feedback reports useful compatibility, ownership and verification
guidance alongside overlapping triggers and repetitive output. It is operator
feedback, not an independently inspected trace or a measured comparison.
Retained probes 056-059 also record receipt-format friction without establishing
an efficiency effect. The current router permits proportional work, but leaf
descriptions and outputs can still demand multiple reviews of an accepted design.

## change contract

Update source instructions, matching onboarding, one existing domain example
and focused instruction tests. Keep the EHS identity, nine skill names, current
manifests/versions, installed release, runtime/protocol contracts and historical
evaluations unchanged. No dependencies, packaging, push, publication or provider
trial. Dogfood inline on disposable local fixtures, not through another model.

## decision challenge

### trigger

This changes the human-facing completion and routing contracts, not execution
authority, persistence or isolation. The existing public-contract trigger applies.

### proposal and claims

Use a short routine path; escalate according to meaningful decisions and risk;
permit flexible reporting; refine existing domain guidance with selected ideas
from Scott Wlaschin. This is a usability/design correction, not a superiority,
cost, safety or productivity claim.

### existing-platform ownership

Hosts and repositories retain permissions, required checks and approval policy.
Optional protocol runs retain their recorded gates. Skills do not enforce a
sandbox or grant delegated, network, publication or merge authority.

### durable differentiated value

EHS owns a concise engineering method: inspect intent and constraints, protect
meaningful behaviour, make consequential decisions visible and support claims
with evidence. No uniqueness or benchmark claim is made.

### strongest counterargument

Pruning could let an agent label a familiar security or compatibility change
routine and skip required scrutiny. Functional modelling could instead add
wrappers, layers and another checklist. Therefore decision reuse must not waive
approvals or verification, and modelling must remain selective and idiomatic.

### claim-to-evidence map

| Claim | Current evidence | Gap | Required evidence |
| --- | --- | --- | --- |
| Obligations overlap | Current leaf triggers and fixed output shapes; reported Flow feedback | No measured overhead | Focused consistency review; no quantified gain |
| Safeguards remain explicit | Existing approval, test-quality and protocol rules | Revised-agent adherence unknown | Static regressions and labelled inline exercises; fresh-session evidence remains separate |
| Workflow/type guidance is applicable | Current domain map plus publisher excerpt and Wlaschin articles | No EHS-effect experiment | One concrete existing example; no efficacy claim |

### minimum credible slice

The approved instruction/doc update and focused tests, followed by one routine
local fix and one consequential-boundary hold. Do not create a new skill,
runtime, harness or mandatory report.

### stop conditions

Stop if implementation requires runtime/manifest/host changes, bypasses required
approval or verification, rewrites old scores, or needs a provider trial. A
failed check is evidence to investigate, not authority to relax the gate.

### verdict

proceed

### rationale

The user approved the trade-off. A bounded source correction can address the
observed ambiguity without claiming that less text necessarily improves agents.

## decision

- Routine work uses scope/constraints, the smallest complete change, meaningful
  verification and a concise outcome/limitations. Reuse equivalent records.
- Inspect material effects, not keywords or line count. Reuse accepted decisions
  when assumptions still hold; new consequential decisions need durable records.
  Familiar patterns never waive security, compatibility or approval obligations.
- Human completion and simplicity reports need useful content, not fixed fields.
  Repository-required formats and existing protocol records remain binding.
- Domain discovery starts with the relevant workflow, valid states, rejections,
  outputs and effects when those distinctions matter. Use existing types and
  validated construction proportionately; keep decisions separate from I/O.
  No FP library, class hierarchy, event store or wrapper-type mandate follows.
- Explain alternative verification when behavioural RED is impractical; ask for
  approval only when repository/user requirements actually require it.
- Critics accept ordinary intent/diff/check evidence. Protocol-specific inputs
  apply only to protocol-backed changes.

## options considered

Keep the old contract: rejected because it preserves conflicting obligations.
Change only the router: rejected because hosts can select leaf descriptions
directly. Add a new modelling skill or receipt schema: rejected as extra surface.
Adopt selective guidance across the existing surfaces: accepted.

## consequences

Human reports are less mechanically predictable; consumers must not treat them
as a fixed schema. Existing evaluators retain their frozen criteria and scores.
Fewer mandatory forms do not establish lower token use, higher quality or host
parity. Required checks and explicit human authority remain unchanged.

## implementation and verification

- Add focused source-contract regressions and observe failure before editing.
- Align router, leaves, AGENTS, manifesto, reviewer prompts and onboarding.
- Improve the existing saved-search example; attribute the modelling inspiration.
- Run validation, focused/full tests, TypeScript and whitespace checks.
- Record inline dogfood in `docs/dogfood/126-proportionate-guidance.md`, including
  actual failures, corrections and limitations. Do not alter prior evidence.

## review condition

Revisit after ordinary fresh-session use reports a missed safeguard or repeated
friction. Do not add text merely to improve a known fixture's score.
