# saved-search DDD change

Scenario: web and mobile have different saved-search shapes. Product wants shareable saved searches. The system needs a canonical saved-search format across web, mobile, API, and persistence.

This example shows the Extremely Hardcore loop on a realistic but compact change.

It illustrates a consequential API/persistence change, not the paperwork required
for routine features. Its domain map includes workflow/state guidance inspired
by Scott Wlaschin; it specifies no functional library or implementation language.
